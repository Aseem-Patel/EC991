Value function iteration, one grid point at a time

The problem is the one on the slides. The household picks next period's assets $a'$ from a grid, consumes what is left, and the value of being at $a$ today is

$$V(a) \;=\; \max_{a' \in \mathcal{A}} \; u\big(R a + y - a'\big) + \beta\, V(a'), \qquad \mathcal{A} = \{a_1, \dots, a_{n_a}\},\quad a_1 = -\phi .$$

Read the right-hand side as a recipe with two ingredients. The first, $u(Ra + y - a')$, is a formula: hand it any $c$ and it returns a number. The second, $V(a')$, is a lookup: it is only known at the $n_a$ points where it is stored. Because $a'$ is only ever chosen from the grid, $V$ is only ever read where it is stored, and no interpolation is needed.

From the converged $V$ to the policy functions

VFI hands back one thing: the column of numbers $V^*(a_i)$, one per grid point. It does not hand back the household's decisions. To get them, fill in the table one more time with $V^*$ in the input row. In each row, the column holding the maximum is the choice.

$$k^*(i) \;=\; \arg\max_{k} \; u\big(R a_i + y - a_k\big) + \beta\, V^*(a_k),$$
$$a'(a_i) = a_{k^*(i)}, \qquad c(a_i) = R a_i + y - a'(a_i).$$

Four steps, and each is one column of the table below.

  1. Find the column of the row maximum. That is an integer $k^*(i)$ between $1$ and $n_a$. The code stores it in pol[i].
  2. Turn the index into an asset level. $a'(a_i) = a_{k^*(i)}$. In code, apol = a[pol]. It is a grid point by construction.
  3. Get consumption from the budget constraint. $c(a_i) = R a_i + y - a'(a_i)$. In code, cpol = y .+ R .* a .- apol. Consumption is not on any grid, and does not need to be.
  4. Check the policies against theory before using them: $c > 0$, $a'$ increasing in $a$, $a'(a) < a$ above the limit when $\beta R < 1$, and the top state not mapping to itself.

In practice there is no separate pass. The last Bellman step of the loop already filled the table with $V_{\ell-1} \approx V^*$ and recorded the row maxima. The table below uses the exact fixed point for the current settings of the worksheet.

Using the policy: follow the indices

Start at the top of the grid and apply $i_{t+1} = k^*(i_t)$ until the household stops moving. Every step lands on a grid point.

The same thing said once more, as code

The slide's double loop and the table are the same object. Row $i$ of the table is one pass through the inner loop, the input row is V0, the output column is V1, and the choice of column is pol.

for i in 1:na                        # one row of the table
    best, kbest = -Inf, 0
    for k in 1:na                    # one cell in that row
        c = R * a[i] + y - a[k]      # off the grid, and fine: u is a formula
        c <= 0 && continue           # dashed cell
        v = u(c) + beta * V0[k]      # V0[k] is a lookup, never an interpolation
        v > best && (best, kbest = v, k)
    end
    V1[i], pol[i] = best, kbest      # red output column; pol is an index
end

Press "Apply $T$ once" and you have executed this block once. Press "Run to convergence" and you have wrapped it in the Step 4 loop. That is all value function iteration is.

Once the loop has stopped, two more lines give the policy functions. They are the same lines as in solve_vfi in src/vfi.jl.

apol = a[pol]                    # index k*(i) -> asset level a'(a_i)
cpol = y .+ R .* a .- apol       # budget constraint -> c(a_i)
